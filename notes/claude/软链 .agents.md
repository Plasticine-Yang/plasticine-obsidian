# 问题

claude code 不识别 `.agents/skills`，需要软链解决

# 解法

## 绝对路径

`ln -s <source> <target>`

把 source 换成 `.agents/skills` 的绝对路径，target 换成 `.claude/skills` 的绝对路径即可，但这个对于 git 仓库来说不通用，换台电脑就无效了

## 相对路径

**重点认知：** 软链的 target 是 **相对“链接自己所在的目录”** 解析的，而不是相对你执行命令时的当前目录

### 反例

`ln -s .agents/skills .claude/skills` 只是把字符串 `.agents/skills` 原样写进链接。这个链接放在 `.claude/` 里，所以系统解析时找的是：

```shell
.claude/.agents/skills   ← 不存在
```

而不是 `./.agents/skills`。结果就是一条**断链**：`ln` 本身不校验 target，命令“成功”了，`ls -l .claude/skills` 也能看到 `-> .agents/skills`，但一访问内容就 `No such file or directory`。

### 正确做法

```shell
ln -s ../.agents/skills .claude/skills
```

## 验证

直接 `ls -l .claude/skills` 查看的是符号链接本身，会输出：

```shell
lrwxr-xr-x ... .claude/skills -> ../.agents/skills
```

这是因为 **`ls -l` 对软链只打印链接条目本身，不会展开目标目录的内容**。所以输出只有一行。

要看到内容，加尾斜杠或去掉 `-l`：

```shell
ls .claude/skills         # 列内容
ls -l .claude/skills/     # 列内容 + 详情（注意结尾的 /）
find -L .claude/skills -maxdepth 1    # find 默认不跟随软链，要加 -L
```
